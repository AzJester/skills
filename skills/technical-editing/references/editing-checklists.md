# Editing checklists

## Before you start

- [ ] What is this document for, and what should the reader do after reading it?
- [ ] Who is the reader, and what do they already know?
- [ ] Which level of edit did the author ask for? If they did not, ask.
- [ ] Is there a governing format — venue template, CDRL DID, style guide? Read it first.
- [ ] What is the deadline, and how much can realistically change before it?

That last question decides everything. A structural finding two days before a submission is not actionable; know that before writing it.

## Substantive pass

- [ ] Purpose and audience are inferable from the document itself
- [ ] The conclusion appears early enough to be found
- [ ] Order serves the reader, not the chronology of the work
- [ ] Every section earns its place; nothing is present out of completeness
- [ ] Claims are supported, and the support sits with the claim
- [ ] Assumptions and limitations are stated rather than implied
- [ ] Alternatives considered and rejected are named where the reader would ask
- [ ] Figures and tables carry argument rather than decorate
- [ ] Nothing overstates what the evidence supports

## Line pass

- [ ] Nominalisations converted back to verbs
- [ ] Unintentional passive given its actor back
- [ ] Compound sentences split where they carry two obligations
- [ ] Every *this*, *it* and *these* has an unmistakable referent
- [ ] Vague quantities either given numbers or marked as judgment
- [ ] Paragraphs open with the sentence that carries their point
- [ ] Transitions exist where the argument turns
- [ ] Acronyms used fewer than three times spelled out instead
- [ ] Lists are parallel in structure and grammatically consistent

## Copy pass

- [ ] One term per concept, used consistently
- [ ] Acronyms expanded at first use; list matches text
- [ ] Units present, consistent, and correctly spaced
- [ ] Significant figures do not imply precision the data lacks
- [ ] Number, date and range formats consistent
- [ ] Figure and table numbers sequential and all cited in text
- [ ] Cross-references resolve
- [ ] References complete, consistent, and in the required style
- [ ] Headings parallel in grammatical form
- [ ] Style guide followed where one governs

## Proofread pass

- [ ] Typos, doubled words, missing words
- [ ] Formatting matches the template — margins, fonts, spacing
- [ ] Page and section numbering correct after any restructuring
- [ ] Front matter matches the body — title, authors, dates, abstract
- [ ] Headers, footers, markings and distribution statements correct on every page
- [ ] Generated elements regenerated: table of contents, lists of figures and tables
- [ ] The file that will actually be submitted is the one you read

## What changes by document type

| Document | Read hardest for | Governing source |
| --- | --- | --- |
| Requirements or specification | Ambiguity, compound obligations, untestable wording | `requirements-dev` |
| Proposal section | Compliance, Section M language, evidence behind claims | `proposal-writing` |
| Technical report | Structure, front matter, distribution statement | `dod-technical-report`, `nasa-sti` |
| Paper | Venue format, citation style, figure and table conventions | `ieee-publishing`, `acm-paper`, `apa-7`, `chicago-turabian` |
| Procedure | One action per step, warnings placed before the hazard | `procedural-documentation` |
| Test report | Conclusions traceable to data, limitations stated | `test-report` |
| Executive memo | The ask in the first line, options with a recommendation | `executive-decision-memo` |
| Interface document | Both sides' assumptions stated, no unowned behavior | `interface-control` |

## Editing your own writing

The levels still apply; the difficulty is that you cannot read it cold. Three things that partially recover the outside view:

- **Put it down.** Overnight if the schedule allows. Nothing else recovers as much.
- **Change its shape.** Different font, print it, read it aloud. Reading aloud finds ambiguity and long sentences reliably, because the lungs run out where the reader's patience does.
- **Read the headings alone, then the figures and captions alone.** If the document's argument does not survive in those two passes, it does not survive a skimming reader either.
